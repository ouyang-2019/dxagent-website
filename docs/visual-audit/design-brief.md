## 动效与交互原则

- 首屏一次分层入场：opacity + 12–20px translateY，350–450ms，间隔约 70–90ms；核心文案和链接无需等待动画才能访问。
- 滚动：进入视口后一次渐入，约 350ms，位移最多 16px；不锁滚动、不劫持滚轮、不依赖动画显示信息。
- hover：卡片轻移 2–4px、箭头位移约 2px；常用操作反馈 120–180ms，不反复播放入场。
- 按压：需要时 scale(.96)，键盘 focus-visible 同样清晰；触屏不依赖 hover。
- 重点工作流程可用轻量的面板转换和状态变化；自动动效不承载必要信息，不在正文/输入过程中争抢注意力。
- 尊重 prefers-reduced-motion：取消自动空间运动和滚动渐入，内容直接出现；原有导航、FAQ、标签页仍可操作。
- 使用现有 CSS/JS 和 IntersectionObserver；列出确切 transition 属性，避免 transition: all 和常驻过量 will-change。
- 不新增前端框架、动画库或全屏 WebGL/自动播放背景视频。真实媒体按需加载，保留尺寸占位；先用静态封面保证首屏。

## 实施顺序与验收（确认后）

1. 先补齐短剧仓库映射，并把九个项目的公开描述逐项绑定到 README/模块依据；保留署名和现有能力边界。
2. 小步提交公共 token 与组件状态；升级主站首屏，再逐个站点/产品区块处理。
3. 每完成一类区块，截图与参考/基线对比；18 页继续覆盖，另测 768px，重复同名状态到 screenshots/after/。
4. 验证现有菜单、焦点、标签页、FAQ、JSON 成功/错误/空输入/清空/快捷键/复制和回退；输入内容不能产生外传请求。
5. build、verify、node --check 必须成功。现仓库没有 lint；需有真实检查命令或明确记录缺项，不能把语法检查冒称 lint。
6. 检查实际文字对比度、44px 触摸目标、alt/图标标签、无 JS 基础内容、减少动效和页面溢出。
7. 一次提交只处理一类改动，例如内容映射、设计 token、主站首屏、产品页主题、博客阅读、工具界面。只选择此次文件，避开现有 cosmetichot/。
